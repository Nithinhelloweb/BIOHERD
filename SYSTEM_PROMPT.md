## Core Features (SIH26128 mandatory)

### 1. Animal Registry
- Register individual animals with: species (cattle, buffalo, goat, sheep, pig, poultry), breed, age, sex, body weight, owner details, geo-tagged location (GPS lat/lng), and a QR-code / RFID tag identifier.
- QR code is generated by the system and downloadable as PDF.
- The farmer can scan a QR code to instantly pull the animal's full health record.
- Each animal has a timeline view of all health events, vaccinations, medications, and notes.
- Herd/flock management: group animals under a single farm entity with bulk operations.

### 2. Symptom Reporting & AI Disease Detection
- Farmer submits a symptom report: select animal (via QR scan or list), describe symptoms via text (Marathi / Hindi / English), upload 1–5 photos, and answer a structured symptom checklist (fever, lethargy, appetite loss, discharge, lameness, skin lesions, respiratory distress, etc.).
- The system performs AI inference:
  - **Image classifier**: EfficientNet-B4 / ViT fine-tuned on livestock disease image datasets. Returns top-3 disease predictions with confidence scores.
  - **Text NLP classifier**: IndicBERT / mBERT fine-tuned on Marathi/Hindi symptom descriptions. Outputs disease probability distribution.
  - **Ensemble fusion**: weighted combination of image + text predictions → final diagnosis probability ranked list.
- Results are shown to the farmer in plain language (not medical jargon) in their preferred language.
- A severity score (low / medium / high / critical) is computed and drives the alert urgency.
- All inference runs asynchronously via Celery; the farmer sees a real-time progress indicator via gRPC server-streaming.
- Results are stored with full audit trail (model version, confidence, timestamp).

### 3. Outbreak Prediction & Geo-surveillance
- LSTM model trained on historical disease event data, weather, and seasonal patterns to predict disease outbreak risk per district / taluka / village over the next 7 / 14 / 30 days.
- PostGIS spatial queries aggregate reported cases into heat zones.
- Government dashboard shows: choropleth map of Maharashtra districts colour-coded by outbreak risk level, time-series graph of reported cases per disease, and a filterable table of all active incidents.
- Automatic escalation: if ≥ N cases of the same disease are reported within a 10 km radius in 72 hours, the system raises an outbreak alert to the district vet and government official.
- Outbreak alerts are sent via push notification (FCM), SMS (Twilio / MSG91), and email.

### 4. Veterinarian Case Management
- All symptom reports are routed to the nearest available district vet's case queue.
- Vet sees: animal profile, symptom report, AI diagnosis suggestions, historical health records, and farmer contact info.
- Vet can: accept case, request more photos/info, prescribe treatment (medicine name, dosage, duration, instructions in the farmer's language), mark case as resolved, or escalate.
- Case status lifecycle: `submitted → assigned → in_review → prescription_issued → follow_up → closed`.
- Vet can initiate a video telemedicine session with the farmer (WebRTC-based, integrated into the Flutter app).
- Prescription is generated as a signed PDF and stored in MinIO; farmer receives it on their app.
- Vet dashboard shows their workload, average response time, and case resolution rate.

### 5. Treatment & Prescription Management
- Curated drug/protocol knowledge base loaded into a vector database (pgvector extension on PostgreSQL).
- RAG pipeline: given a confirmed disease, retrieve relevant treatment protocols, drug dosages (adjusted for species and body weight), withdrawal periods, and contraindications.
- Vets see AI-generated treatment suggestions (clearly labelled as AI, not final) alongside the knowledge base sources.
- Prescription records are linked to the animal's health timeline.
- Drug inventory tracking per district veterinary centre (DVC): stock levels, expiry dates, reorder alerts.

### 6. Vaccination Management
- Vaccination schedule engine: based on animal species, age, region, and government-mandated vaccination calendar (FMD, BQ, HS, PPR, Anthrax, etc.).
- System auto-generates upcoming vaccination reminders for farmers (push + SMS, 7 days and 1 day before due date).
- Vet records vaccination: vaccine name, batch number, manufacturer, dose, date administered, next due date.
- Vaccination certificates are generated as signed PDFs with QR code for verification.
- Government dashboard shows district-level vaccination coverage as a percentage of registered livestock population.
- Missed vaccination tracking: animals that are overdue are flagged for follow-up.

### 7. IoT Sensor Integration & Vitals Monitoring
- Ingest real-time sensor streams via Kafka: ear-tag sensor data (body temperature, heart rate, activity index, rumination time), collar GPS location.
- Isolation Forest anomaly detection runs on a sliding window of each animal's vitals.
- Z-score threshold alerts: if body temperature > configurable threshold for species (e.g., > 39.5°C for cattle) for > 30 minutes, trigger an alert.
- Vitals dashboard per animal: real-time line charts of temperature, heart rate, activity with configurable time ranges (1h / 6h / 24h / 7d).
- Sensor data stored in TimescaleDB hypertables with automatic chunk compression and data retention policies (raw: 30 days, 1-minute aggregates: 1 year).

### 8. Telemedicine & Video Consultation
- Farmer requests video consultation from within a case.
- Vet accepts and both parties join a WebRTC session embedded in Flutter (using `flutter_webrtc`).
- Signalling server: a lightweight FastAPI WebSocket endpoint manages SDP offer/answer and ICE candidate exchange.
- STUN/TURN server (Coturn) for NAT traversal.
- Session is recorded (with explicit farmer consent) and stored in MinIO linked to the case record.
- Consultation notes entered by vet during/after the call are saved to the case.

### 9. Multilingual Support (Marathi / Hindi / English)
- All farmer-facing UI strings, symptom labels, disease names, prescription text, and push notifications support Marathi, Hindi, and English.
- The AI disease name and description output is translated using a post-processing translation layer (IndicTrans2 or Google Translate API as fallback).
- System detects device locale and defaults to the appropriate language.
- Farmers can switch language in-app at any time; preference is persisted per user profile.
- Voice input for symptom description (speech-to-text via on-device Whisper or Google STT, transcribed to text for AI processing).

### 10. Offline-First Architecture
- Flutter app uses local SQLite (via `drift`) as the primary offline store.
- All farmer actions (symptom reports, animal registration, vaccination records) are written locally first.
- A background sync queue flushes local writes to the server when connectivity is restored, with conflict resolution (server-wins for shared records, client-wins for new records).
- Critical reference data (symptom checklist, disease descriptions, drug list, animal breeds) is pre-loaded and cached locally on first launch.
- The app shows a clear connectivity status indicator and gracefully degrades features that require live server connectivity (AI inference, video calls).

### 11. Alerts & Notification System
- Multi-channel alerts: FCM push (mobile), Web Push (browser), SMS (MSG91 / Twilio), Email (SMTP).
- Alert types: disease detection result ready, case assigned/updated by vet, vaccination due, IoT vitals anomaly, outbreak warning in district, prescription issued.
- Alerts are stored in the database with read/unread status and a notification centre in the app.
- Government officials receive aggregated daily digest emails (configurable time) with district-level summaries.
- Alert preferences are configurable per user.

### 12. Reports & Analytics
- Farmer: downloadable PDF health history report for an animal or entire herd (for insurance claims, sale transactions).
- Vet: weekly/monthly case summary PDF, prescription audit trail.
- Government: state-level dashboard with exportable Excel/CSV — disease incidence by district, vaccination coverage, vet response times, economic impact estimates.
- All reports are generated asynchronously via Celery and delivered via in-app download + email.
- Pre-built Grafana dashboards for operational metrics (API latency, AI inference time, DB query performance).

### 13. Government Mock Data Integration
- Since live government livestock DB access is not available for the MVP, build a seeded mock dataset representing Maharashtra's 36 districts with realistic livestock population, historical disease event records (2019–2025), vaccination coverage data, and vet centre locations.
- Expose an admin-only API endpoint to load/refresh this seed data.
- Design the integration layer as an abstract `GovernmentDataAdapter` interface so it can be swapped for the real NLMD / Maharashtra AHD API when access is granted without changing business logic.

## Security Requirements (all mandatory)

### Authentication & Authorization
- RS256-signed JWTs. Access token TTL: 15 minutes. Refresh token TTL: 7 days (rotated on each use).
- Refresh tokens stored in Redis with a device fingerprint binding — revocable per device.
- All API endpoints require a valid JWT except: `POST /auth/register`, `POST /auth/login`, `GET /health`.
- Row-level security (RLS) in PostgreSQL: farmers can only read/write their own animals and reports; vets can read cases in their assigned district only; government officials see only their jurisdiction.
- RBAC enforced at every gRPC method via an interceptor.

### Transport Security
- TLS 1.3 end-to-end. No HTTP (redirect to HTTPS). gRPC over TLS.
- Certificate pinning in the Flutter mobile app.
- HSTS header with `max-age=31536000; includeSubDomains`.

### Input Validation & Injection Prevention
- All FastAPI request bodies validated with Pydantic v2 strict mode.
- All gRPC messages validated via protobuf field constraints.
- Parameterised queries everywhere — no raw SQL string concatenation.
- SQLAlchemy ORM with asyncpg driver; no `text()` without explicit bind parameters.
- File upload validation: MIME type check (server-side magic bytes, not just extension), max size 10 MB per file, virus scan via ClamAV before storing to MinIO.
- Image EXIF stripping before storage to prevent metadata leakage.

### API Security
- Rate limiting: 100 req/min per IP (unauthenticated), 500 req/min per user (authenticated), 10 req/min for auth endpoints.
- CORS: whitelist only known origins (Flutter web domain, admin portal domain).
- CSRF protection on all state-changing REST endpoints (Double Submit Cookie pattern).
- API versioning (`/api/v1/`). Breaking changes require a new version.

### Data Security
- Sensitive fields (Aadhaar numbers if collected, phone numbers, GPS coordinates of farmer home) encrypted at rest using AES-256-GCM via SQLAlchemy encrypted column type.
- MinIO buckets: private by default, accessed only via pre-signed URLs (TTL: 1 hour).
- Database backups: automated daily pg_dump to encrypted MinIO bucket, retained 30 days.
- Secrets management: all credentials via environment variables loaded from Kubernetes Secrets (never hard-coded).

### Logging & Audit
- Structured JSON logging via Python `structlog`. Log levels: DEBUG (dev), INFO (staging/prod).
- No PII in logs — user IDs and animal IDs only, never names or phone numbers in log lines.
- Jaeger distributed tracing on all FastAPI endpoints and gRPC calls with 100% sampling in dev, 5% in prod.
- Security events (failed login, invalid token, rate limit hit, file upload rejection) logged to a dedicated `security_events` table.

### Dependency & Container Security
- `pip-audit` and `safety` run in CI on every PR — block merge on critical CVEs.
- Docker images built from `python:3.12-slim` base; no root user in containers.
- Kubernetes PodSecurityContext: `runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`.
- Network policies: each microservice can only talk to services it explicitly needs.

## AI/ML Pipeline Specifications

### Models to implement
1. **Image Disease Classifier** — EfficientNet-B4 pretrained on ImageNet, fine-tuned on livestock disease dataset. Input: up to 5 images resized to 384×384. Output: top-5 disease classes with softmax probabilities. Serve via ONNX Runtime for latency.
2. **Text Symptom Classifier** — `ai4bharat/indic-bert` fine-tuned on symptom text (Marathi/Hindi/English). Supports multilingual input without translation. Output: disease probability distribution.
3. **Ensemble Fusion** — weighted average (image: 0.6, text: 0.4) with calibration. If no image provided, text-only mode.
4. **Outbreak LSTM** — sequence model on 30-day sliding window of [case_count, temperature, rainfall, season_flag] per district. Predicts risk score 0–1 for next 7 / 14 / 30 days.
5. **Vitals Anomaly Detector** — Isolation Forest trained per species on normal vitals distributions. Online scoring on each incoming Kafka sensor event.
6. **RAG Treatment Advisor** — document chunks from WHO/FAO/ICAR livestock treatment manuals embedded with `sentence-transformers/paraphrase-multilingual-mpnet-base-v2`, stored in pgvector. Query: confirmed disease name + animal species + weight → top-5 relevant protocol chunks → fed to a local LLM (Ollama with `mistral:7b-instruct`) for synthesis. The LLM response is clearly labelled as AI-assisted.

### Inference pipeline
- Celery task `run_disease_inference(symptom_report_id)` is triggered on symptom report submission.
- Task downloads images from MinIO, runs image model → text model → ensemble → stores `detection_results` row.
- Progress events are streamed back to the Flutter client via gRPC server-streaming (subscribed at job submission).
- Inference results cached in Redis for 24 hours (key: `inference:{symptom_report_id}`).
- MLflow logs: model version, input hash, prediction, confidence, latency on every inference call.
